# Règles anti-erreurs n8n — rétrospective de la n°1 (contrôle SIRET)

Erreurs commises dans le code/JSON de la n°1 (à ne plus reproduire dans les prochains workflows) :

| # | Erreur | Symptôme dans n8n | Règle pour la suite |
|---|---|---|---|
| 1 | `Object.keys($json.body)` sans vérifier le type — le webhook peut envoyer le body en **string** (Content-Type non reconnu) | `A 'json' property isn't an object [item 0]` | Toujours parser défensivement : `let body = $json.body; if (typeof body === "string") { try { body = JSON.parse(body) } catch(e) { body = null } } if (!body \|\| typeof body !== "object" \|\| Array.isArray(body)) body = $json;` |
| 2 | `.first()` dans un nœud **Code** (`$input.first()`, `$('X').first()`) | `Can't use .first() here [item 0]` (sur certaines versions) | Dans un nœud Code : utiliser `$json` (item courant — suffit quand un seul item entre), `$('Nom').all()[0].json` ou `$('Nom').item.json`. Éviter `.first()`. |
| 3 | Double `=` (`==`) dans une expression — on a tapé `=` dans un champ déjà en mode expression (fx bleu) | l'expression est invalide, le nœud plante | Un seul `=` max. Mode fixe (gris) → tape `=expr` ; mode expression (fx bleu) → tape `expr` sans `=`. **Vérif** : ⋯ → Export → chercher `"=="` → aucun. |
| 4 | `rightValue: "==true"` dans le nœud IF (même bug n°3) | condition douteuse | En boolean, préférer l'opération `is true` (singleValue, pas de Value 2). |
| 5 | Lire `$json.champ` au nœud **suivant un nœud en « On Error: Continue »** (ex: PATCH placeholder qui échoue) → l'item transmis est `{error:...}`, pas les données | champ vide/inattendu dans l'e-mail et la réponse webhook | Après un nœud en continue-on-fail, référencer explicitement le nœud amont : `{{ $('Nom du nœud').item.json.champ }}`. |
| 6 | `jsonBody` mal formé (`=={{ ... }}`) sur un HTTP Request en body JSON | erreur d'expression au nœud | Body JSON en expression : `={ "champ": $json.x }` (un seul `=`, pas de guillemets autour de l'objet). |
| 7 | Faute de frappe dans une adresse (`madelaine-riviera.fr`) | e-mail rejeté plus tard | Relire les valeurs en dur avant Save. |
| 8 | Retour du nœud Code : `json` doit être un **objet** | `In the returned data, every key named 'json' must point to an object` | `return [{ json: { ... } }]` ou `return { json: { ... } }` — les deux formes marchent, mais `json` = objet obligatoire. |

Règles générales :
- Toujours **Save** avant de tester (point orange sur l'onglet = non sauvegardé).
- Nœuds externes (HTTP, SMTP) en phase placeholder : **On Error = Continue (regular output)** + **Never Error** + timeout 10 s.
- En mode test, le webhook répond **200 dès la réception** même si l'exécution échoue après → le vrai statut est dans **Executions** (vert/rouge), pas dans le terminal.
- Windows PowerShell : `curl` est un alias cassant → `curl.exe` ou `Invoke-RestMethod`, **une commande à la fois** (coller plusieurs commandes d'un coup ouvre un bloc `>>` et déforme le JSON → 422 de n8n).
- Aucun secret en dur dans le repo GitHub : placeholders uniquement (`Bearer PLACEHOLDER`, `https://api.madeleine-riviera.fr`).

| 9 | Faute de frappe `lenght` au lieu de `length` dans une expression IF (`$json.data.lenght > 0`) | l'expression vaut toujours false → mauvaise branche | Relire les noms de propriétés dans les expressions ; en cas de doute, tester l'expression dans un nœud Set/Debug. |
| 10 | Webhook en mode `Using 'Respond to Webhook' Node` testé **avant** d'avoir connecté de nœud Respond to Webhook | `No Respond to Webhook node found in the workflow` | Normal en cours de construction : connecter d'abord les nœuds Respond to Webhook (un par branche, plusieurs autorisés), ou mettre temporairement le webhook en Respond = `Immediately` puis remettre `Using 'Respond to Webhook' Node` avant la recette. |
| 11 | En mode test, le terminal renvoie `{"message":"Error in workflow"}` (HTTP 500) | l'exécution est morte **avant** d'atteindre un nœud `Respond to Webhook` : branche non branchée, ou nœud externe sans On Error Continue qui a planté | Dans **Executions**, regarder quel nœud est le dernier (rouge) ; s'assurer que **chaque branche** du workflow se termine par un `Respond to Webhook` et que tous les HTTP externes ont On Error = Continue + Never Error. Le 200 du webhook en mode test ne signifie rien : le vrai statut est dans Executions. |
| 12 | Référence à un nœud dont le nom contient une **apostrophe** (`Extraire l'événement`) écrite à la main sans échappement dans une expression ou un Code | `Invalid JSON in 'Response Body' field` / erreur de syntaxe dans le Code | Toujours écrire `$('Extraire l\'événement')` (apostrophe échappée `\'`) — c'est ce que n8n génère quand on choisit le nœud dans la liste déroulante `$('`. Ne jamais taper la référence à la main avec l'apostrophe brute. |
| 13 | Nœud remplacé par un FAUX GET en gardant l'original → le remplaçant hérite d'un suffixe (`1`, `0`) et les références `$('Nom')` visent le nœud non exécuté | dans le nœud Code aval : `Cannot read properties of undefined (reading 'json')` → 500 « Error in workflow » | Les références `$('...')` sont résolues **par nom** : supprimer le nœud HTTP **avant** d'ajouter le Code remplaçant et lui donner **exactement** le même nom. Dans un Code, préférer `$('Nom').all()[0].json` à `.item.json` (et jamais `.first()`, règle 2). |
| 14 | `Respond to Webhook` (respondWith = JSON) avec un Response Body en littéral objet `={ "a": 1, "b": $('N').item.json.x }` | `Invalid JSON in 'Response Body' field` → 500 « Error in workflow » | Le Response Body doit évaluer vers une **chaîne** JSON : utiliser `={{ JSON.stringify({ a: 1, b: $('N').item.json.x }) }}`. (Le body JSON d'un **HTTP Request**, lui, accepte le littéral objet `={ ... }` — ne pas confondre.) |
| 15 | Body OAuth2 (HTTP Request, Body Content Type `Form URL Encoded`, mode String) avec un `=` devant la chaîne | le `=` fait croire à une expression → nœud en erreur | Body = la chaîne urlencoded **sans `=`** : `grant_type=client_credentials&client_id=...&client_secret=...` |
| 16 | Après une chaîne de IF/HTTP, lire `$json.champ` en pensant que c'est l'item d'origine | champ vide/`undefined` (ex. `$json.order_id` après un GET = réponse HTTP `{data:...}`) | Règle 5 généralisée : après un IF ou un HTTP, `$json` = la sortie du dernier nœud ; pour les champs d'un item amont, référencer explicitement `$('Nœud amont').item.json.champ`. Ne jamais copier-coller le `jsonBody` dans un nœud Code. |
| 17 | Schedule Trigger cron sans timezone ; URL avec un retour à la ligne final | exécution à 6h UTC au lieu de 6h Paris ; requête cassée | Toujours régler **Timezone `Europe/Paris`** dans le trigger ; jamais de `\n` à la fin d'une URL. |
| 18 | Alerte sur échec de workflow | exécutions en erreur invisibles | Pattern retenu (n°7) : **Error Trigger** → e-mail au bureau (workflow, nœud en erreur, message, lien d'exécution). Garder **Never Error + On Error Continue** sur les appels externes pour qu'un échec ponctuel n'arrêtte pas tout le lot ; l'Error Trigger attrape alors les vraies erreurs structurelles. |
